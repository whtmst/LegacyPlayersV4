# Полное руководство по TurtleLogs API

Данная документация предназначена для разработчиков, желающих интегрировать данные проекта TurtleLogs в свои приложения. TurtleLogs предоставляет API для доступа к обширной базе данных игровых миров (Vanilla, TBC, WotLK), информации о персонажах, гильдиях, а также детальной статистике рейдовых сражений и логов.

---

## 1. Аутентификация и безопасность

### API Токены
Токен доступа (`API Token`) является персональным идентификатором пользователя.

*   **Назначение:**
    *   Идентификация запроса для системы лимитов.
    *   Доступ к приватным данным персонажей (если установлены настройки приватности).
    *   Доступ к методам управления данными (для владельцев серверов).
    *   Получение персонализированной информации о персонажах и гильдиях.
*   **Где получить:** В личном кабинете на сайте в разделе [API Tokens](https://www.turtlogs.com/account/api). При создании вы сами задаете название и срок жизни ключа.
*   **Важно:** Токен передается в заголовке запроса. **Никогда не передавайте токен в параметрах URL.**

### Заголовки (Headers)
Для каждого запроса рекомендуется передавать следующий набор заголовков:

| Заголовок | Обязателен | Описание |
|:---|:---:|:---|
| `X-Authorization` | Нет* | Ваш персональный API токен. *Обязателен для методов `ServerOwner` и приватных данных. |
| `X-Language` | Нет | Код языка (например, `ru`, `en`, `de`). Влияет на возвращаемые названия (предметы, расы и т.д.). По умолчанию — `en`. |
| `X-Expansion` | Да** | ID дополнения: `0` (Vanilla), `1` (TBC), `2` (WotLK). **Обязателен для поиска предметов, заклинаний и NPC. |

## 2. Ограничения (Rate Limits) и Коды ответов

В системе TurtleLogs действуют строгие правила защиты от злоупотреблений и автоматического парсинга.

### Лимиты запросов
На уровне сетевого шлюза (Nginx) установлены следующие ограничения:
*   **Частота:** 500 запросов в секунду (500 r/s) на один IP-адрес.
*   **Всплески:** Допускается кратковременный всплеск до 500 запросов (burst).
*   **Превышение:** При превышении лимита сервер вернет ошибку **429 Too Many Requests**. Повторное нарушение может привести к временной блокировке IP.

### Стандартные коды ответов
*   `200 OK` — Запрос успешно обработан.
*   `401 Unauthorized` — Токен отсутствует, недействителен или срок его действия истек.
*   `403 Forbidden` — У вас недостаточно прав (например, вы пытаетесь получить данные через метод `ServerOwner`, не являясь владельцем сервера).
*   `404 Not Found` — Запрошенный ресурс (персонаж, предмет, лог) не найден.
*   `429 Too Many Requests` — Превышен лимит запросов.

## 3. Обзор модулей API

Базовый URL: `https://www.turtlogs.com/API`

### 3.1 Data API (Справочники)
Позволяет получать информацию из игровой базы данных. Почти все методы публичные.

*   **Сервера (`/data/server`):** Возвращает список игровых миров, их текущий патч и принадлежность к дополнению.
*   **Предметы (`/data/item/<exp_id>/<id>`):** Возвращает данные о предмете (качество, класс, уровень, иконка).
*   **Локализация (`/data/.../localized`):** Позволяет получить названия сущностей (расы, классы, спеки) с учетом заголовка `X-Language`.

**Ключевые поля ответа:**
- `id`: Уникальный ID сущности.
- `expansion_id`: К какому дополнению относится сущность.
- `localization_id`: ID для поиска перевода в базе локализации.

### 3.2 Armory API (Оружейная)
Сердце проекта, содержит данные о миллионах персонажей.

*   **Просмотр персонажа (`/armory/character_viewer/<server>/<name>`):** Возвращает комплексный объект, включающий:
    - Текущую экипировку (`gear`).
    - Статистику (`stats`: сила, ловкость, спд и т.д.).
    - Таланты и специализацию (`talent_specialization`).
    - Профессии.
*   **Гильдии (`/armory/guild_view/<server>/<name>`):** Содержит список участников, их ранги и базовую информацию.
*   **Метод ServerOwner (`/armory/character/by_uid/<uid>`):** Специальный метод для владельцев серверов, позволяющий сопоставить внутреннего игрока с данными TurtleLogs.

### 3.3 Tooltip API (Подсказки)
Оптимизированные методы для встраивания подсказок. Возвращают данные, необходимые для отрисовки тултипа в стиле WoW.

*   `GET /tooltip/item/<exp_id>/<id>` — Возвращает характеристики предмета, текст эффектов и требования.
*   `GET /tooltip/character/<id>` — Компактная карточка персонажа.

### 3.4 Instance API (Логи и статистика)
Доступ к результатам рейдовых походов.

*   **Экспорт лога (`/instance/export/meta/<id>`):** Мета-данные конкретного убийства босса или прохождения подземелья.
*   **Рейтинги (`/instance/ranking/dps`):** Позволяет получать списки лучших игроков по нанесенному урону, исцелению или угрозе (threat). Можно фильтровать по сезонам.
*   **Speed Runs (`/instance/speed_run`):** Рейтинг гильдий по времени прохождения рейдовых зон.

## 4. Примеры использования

### Пример 1: Получение детальных данных о персонаже (Публичный доступ)
Запрос данных о персонаже "Thrall" на сервере "TurtleWoW".

```bash
curl -X GET "https://www.turtlogs.com/API/armory/character_viewer/TurtleWoW/Thrall" \
     -H "X-Language: ru"
```

### Пример 2: Запрос через ServerOwner (Требуется токен)
Метод для синхронизации данных игрового сервера.

```bash
curl -X GET "https://www.turtlogs.com/API/armory/character/by_uid/129173537828124" \
     -H "X-Authorization: your_sha3_token_here"
```

### Пример 3: Получение рейтинга DPS за текущий сезон
```bash
curl -X GET "https://www.turtlogs.com/API/instance/ranking/dps" \
     -H "X-Expansion: 0"
```

## 5. Техническая справка

Если вы обнаружили ошибку в данных или поведении API, вы можете изучить исходный код реализации:

*   **Обработка запросов:** `Backend/src/main.rs` (основная маршрутизация).
*   **Логика токенов:** `Backend/src/modules/account/tools/token.rs`.
*   **Система прав доступа:** Папка `Backend/src/modules/account/guard/`.
*   **Модели данных:** Папки `dto` и `domain_value` внутри соответствующих модулей бэкенда.

*Для получения детальных схем JSON (DTO) рекомендуется использовать встроенную документацию Swagger UI по адресу: `https://www.turtlogs.com/API/index.html`.*
